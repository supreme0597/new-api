## 修复用量统计（渠道分析）跨库查询失败 ✅

**问题**：测试环境部署后用量统计看不到数据，30天条件不生效。

**根因**：`LOG_DB` 和 `DB` 可能是不同的数据库（通过 `LOG_SQL_DSN` 环境变量配置）。原代码在 `LOG_DB` 上执行 `JOIN channels ON logs.channel_id = channels.id`，但 `channels` 表只在主库 `DB` 中，日志库 `LOG_DB` 没有 `channels` 表，导致 JOIN 失败，查询返回空数据。

**修复方案**：移除所有 `JOIN channels`，改为两步查询：
1. 先从主库 `DB` 查询渠道ID和来源映射
2. 再用 `IN` 条件在日志库 `LOG_DB` 上过滤

**提交**：`a6138634`

## 修复 MySQL DATE() 返回 ISO 格式时间 ✅

**问题**：测试环境（MySQL）用量趋势的时间格式显示为 `04-25T00:00:00Z`。

**根因**：项目自动为 MySQL DSN 加 `parseTime=true`，导致 go-sql-driver 将 `DATE()` 返回的 `DATE` 类型自动转为 Go 的 `time.Time`。GORM 扫描到 struct 的 `string` 字段后，JSON 序列化走 `time.Time.MarshalJSON()`，输出 ISO 格式 `2026-04-25T00:00:00Z`。

**修复**：`getTimeBucketExpr` 中 day 粒度从 `DATE(FROM_UNIXTIME(...))` 改为 `DATE_FORMAT(FROM_UNIXTIME(...), '%Y-%m-%d')`。`DATE_FORMAT` 返回 `VARCHAR` 字符串，不会被驱动转为 `time.Time`。

**提交**：`74358dbc`

## 修复用量统计跳转 Dashboard 看不到数据 ✅

**问题**：从用量统计详情页点击用户跳转到 Dashboard 看不到数据。

**根因（3个问题）**：
1. 跳转 URL 只传了 `username`，没传时间范围 → Dashboard 用默认时间（1天），不是用量统计当前的30天
2. Dashboard 没从 URL 读取时间戳参数 → 无法同步查询条件
3. 后端 `GetQuotaDataByUsername` 没有 `GROUP BY model_name, created_at` → 返回的数据格式与 `GetAllQuotaDates` 不一致

**修复**：
1. `Detail.jsx` 跳转时追加 `start_timestamp` 和 `end_timestamp` 到 URL
2. `useDashboardData.js` 从 URL 参数读取时间戳，覆盖默认时间范围
3. `model/usedata.go` 中 `GetQuotaDataByUsername` 添加 `SELECT ... GROUP BY model_name, created_at`，与 `GetAllQuotaDates` 保持一致

## 修复 Dashboard 图表排序和柱子宽度 ✅

**问题**：
1. Dashboard 用量趋势图表时间排序错乱
2. 模型调用次数排行柱状图柱子太粗

**根因**：
1. VChart 自动将 X 轴 `Time` 识别为时间轴，尝试解析 `MM-DD HH:00` 格式字符串导致排序错误
2. 没有设置 `bandPadding`，VChart 默认柱子占满分类空间

**修复**：
1. `spec_line`（模型消耗分布）和 `spec_model_line`（调用趋势）添加 `axes: [{ orient: 'bottom', type: 'band' }]`，阻止自动时间解析
2. `spec_rank_bar`（模型调用次数排行）添加 `axes` 并设置 `bandPadding: 0.3, paddingInner: 0.4`，减小柱子宽度

## 修复用量统计趋势图表时间排序错乱 ✅

**问题**：用量统计首页「各来源使用次数趋势」和详情页「用量趋势」选择30天按天粒度时，时间排序错乱。
