# 2026-04-25

## 采样任务渠道并行 + 日志增强 + 使用日志记录 + 并发竞争修复 + NULL 扫描修复

**渠道并行：** `RunSamplingTask` 中每个渠道启动独立 goroutine，渠道内模型保持串行间隔。计数器改用 atomic，结果列表加 mutex 保护。

**进度显示：** 前端"当前：渠道/模型"跳动 → 固定显示"多个渠道并行采样中"。

**系统日志增强：** `sampleModelPerformance` 内部每个关键节点都加了 `common.SysLog`/`SysError`。

**使用日志记录：** 新增 `RecordSamplingLog` 函数，采样成功/失败时写入 `Log` 表（type=LogTypeConsume, quota=0），Other 字段含 `is_sampling: true`。

**并发竞争修复：** `UpsertModelPerformance` 先 `First` 再 `Create`/`Updates` 的读-写竞争，在渠道并行后导致重复插入/主键冲突 → 500。修复：加 `sync.Mutex` 串行化 upsert。同时修复 `isRecordNotFoundError` 使用字符串比较 → 改用 `errors.Is(err, gorm.ErrRecordNotFound)`。

**NULL 扫描修复（根因）：** `GetModelPerformanceList` 中 `results` 结构体用 `string` 接收 `channels.name`/`channels.source`，当数据库值为 NULL 时 GORM 扫描报错 → 500 Internal Server Error。修复：改为 `*string` 指针类型，组装时处理 nil。

## 模型排行评分公式说明优化

在模型响应速度排行榜页面的顶部说明卡片中，新增了两行具体的分项计算公式：
- `TPS评分 = min(实际TPS / {tps基准}, 1) × 100，满分100`
- `TTFT评分 = max(0, (1 - 实际TTFT / {ttft基准})) × 100，满分100`

同时把「颜色含义」从纯文字标签改成了带分数阈值的标签：
- 优秀 ≥80、良好 ≥60、一般 ≥40、较差 ≥20、很差 <20

让用户能直观看到每个指标的分是怎么算出来的，以及综合评分多少分对应什么颜色，规则更加清晰。

## 分渠道进度条（方案B）

**根因**：并行采样时多个 goroutine 交替调用 `updateSamplingTaskProgress`，采样完成后使用旧的 `currentDone` 值覆盖全局状态，导致进度条倒退。

**实现**：
- 后端新增 `ChannelSamplingStatus` 结构体，每个渠道独立维护 done/success/failed/total/message
- `RunSamplingTask` 初始化时为每个渠道创建状态对象，goroutine 内维护渠道级计数器
- 采样过程中同时更新全局进度和渠道进度，完成后用 `doneAtomic.Load()` 避免旧值覆盖
- 前端在采样状态卡片中增加「渠道进度」区域，每个渠道独立显示进度条、成功/失败数、当前消息
- 渠道进度条颜色：完成且全成功=绿色，完成但有失败=红色，进行中=蓝色

**修改文件**：
- `model/sampling_task.go` - 数据结构 + 进度更新逻辑
- `web/src/pages/Setting/Model/SettingModelSampling.jsx` - 前端UI
- `web/src/i18n/locales/zh-CN.json` / `en.json` - 翻译

## 采样结果成功/失败列表同时查看修复

**根因**：`<Collapse accordion>` 开启了 Semi Design 手风琴模式，同一时刻只能展开一个面板，导致成功列表和失败列表互斥。

**修复**：去掉 `accordion` 属性，改为普通模式允许多面板同时展开，并设置 `defaultActiveKey` 让两个列表默认都展开。

**修改文件**：
- `web/src/pages/Setting/Model/SettingModelSampling.jsx`

## 采样日志令牌列空标签修复

**根因**：`RecordSamplingLog` 写入时 `TokenName` 为空字符串，前端令牌列渲染只判断了 `type`，没判断 `text` 是否为空，导致空字符串也渲染了一个灰色 `<Tag>`。

**修复**：前端 `UsageLogsColumnDefs.jsx` 令牌列的渲染条件增加 `&& text`，空值时不渲染任何内容。

**修改文件**：
- `web/src/components/table/usage-logs/UsageLogsColumnDefs.jsx`
