### 最终设计要点

**页面一：渠道来源对比列表（/channel-analytics）**
- 概览卡片：来源总数、总调用次数、总 Token 消耗、活跃用户数
- 来源对比表格：排名、来源、渠道数、活跃用户、调用次数、Token 消耗、操作
- 图表区（各模块自带条件）：
  - 各来源调用量对比（柱状图）
  - 各来源使用次数趋势图（折线图，自带 范围+粒度 选择器）

**页面二：来源详情页（/channel-analytics/:source）**

- 用量趋势区块：
  - 左侧：分段控制器（Segmented Control）切换「调用次数 / Token 消耗」
  - 右侧：范围 + 粒度选择器
- 活跃用户排行区块：
  - 范围选择器 + Top N 选择器（5/10/20/50，默认 10）
- 去掉 Tab 栏和模型统计（项目中已有「模型响应速度排行榜」页面）

### 关键设计决策
1. **渠道来源是通用属性**：`Channel.Source` 字段已经是全渠道字段，非测试渠道专属
2. **按来源统计 TPS/TTFT 不建议做**：当前 `ModelPerformance` 只记录测试渠道采样数据，`Log` 表没有 TTFT 字段，实现复杂
3. **条件筛选采用「模块独立」模式**：每个图表/区块自带范围+粒度，右上角不做全局筛选，避免冲突
4. **数据维度切换用分段控制器**：比 Tag 切换更清晰，放在图表标题下方

### 后端依赖分析
- 用户量统计：`Log` 表 JOIN `channels` 按 `source` 分组 `COUNT(DISTINCT user_id)` 可行
- 趋势图聚合：需要后端支持按时间范围+粒度（hour/day/week/month）聚合查询
- 活跃用户排行：同样需要按时间范围筛选

## 渠道来源分析功能实现

基于 mockup 设计完成了渠道来源分析功能的完整实现。

### 新增文件

1. **`model/channel_analytics.go`** — 后端数据模型和查询
   - `ChannelSourceOverview` — 概览统计结构
   - `ChannelSourceStat` — 按来源分组统计
   - `ChannelSourceTrendPoint` — 趋势数据点
   - `ChannelSourceUserRanking` — 用户排行
   - `GetChannelSourceOverview()` — 概览数据（来源数/调用数/Token/活跃用户）
   - `GetChannelSourceStats()` — 各来源统计（含渠道数/活跃用户/调用数/Token）
   - `GetChannelSourceTrend()` — 趋势数据（支持 hour/day/week 粒度，跨 DB 兼容）
   - `GetChannelSourceDetail()` — 单来源详情
   - `GetChannelSourceUserRanking()` — 活跃用户排行（Top N）
   - `getTimeBucketExpr()` — 跨 DB 时间分组表达式（MySQL/PostgreSQL/SQLite）

2. **`controller/channel_analytics.go`** — API handler
   - `GET /api/channel-analytics/overview` — 概览
   - `GET /api/channel-analytics/sources` — 来源列表
   - `GET /api/channel-analytics/trend` — 趋势数据
   - `GET /api/channel-analytics/source/:source` — 来源详情
   - `GET /api/channel-analytics/source/:source/users` — 用户排行

3. **`web/src/pages/ChannelAnalytics/index.jsx`** — 列表页
   - 概览卡片、来源对比表格、环形图、柱状趋势图
   - 时间范围 + 粒度选择器

4. **`web/src/pages/ChannelAnalytics/Detail.jsx`** — 详情页
   - 分段控制切换（调用次数/Token 消耗）
   - 用量趋势柱状图
   - 活跃用户排行表格（Top N 可选）
   - 页面级统一时间范围
