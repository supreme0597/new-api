## 我的渠道功能修复 - 公共渠道不显示 Bug ✅ 已完成

**Bug 描述：**
普通用户进入「我的渠道」页面，只能看到个人渠道，看不到超级管理员创建的公共渠道（`owner_user_id IS NULL`）。

**根因分析：**
`model/channel.go` 的 `ApplyChannelViewScope` 函数中，SQL WHERE 子句存在三值逻辑问题：
```go
return query.Where("(owner_user_id IS NULL OR owner_user_id = ?) AND owner_user_id != ?", userId, TestChannelOwnerUserId)
```

对于 `owner_user_id IS NULL` 的行：
- `owner_user_id IS NULL` → `TRUE`
- `owner_user_id = userId` → `NULL`（NULL 与任何值比较都是 NULL）
- `TRUE OR NULL` → `TRUE`
- `owner_user_id != -999` → `NULL`（NULL 与任何值比较都是 NULL）
- **`TRUE AND NULL` → `NULL`**

在 SQL 的 WHERE 子句中，`NULL` 被视为 `false`，所以所有 `owner_user_id IS NULL` 的公共渠道都被过滤掉了。

**修复方案：**
简化为 `WHERE owner_user_id IS NULL OR owner_user_id = ?`，因为 `userId` 是正整数，不可能等于 `-999`（TestChannelOwnerUserId），所以 `owner_user_id = userId` 已经自然排除了测试渠道。

**修改的文件：**
- `model/channel.go` — 修复 `ApplyChannelViewScope` 函数（第 114-121 行）

## 我的渠道 - 渠道分类筛选器不生效 Bug ✅ 已修复

**Bug 描述：**
在「我的渠道」页面，渠道分类（Public/Private）筛选器在 UI 中显示，但选择后没有任何筛选效果。

**根因分析：**
`web/default/src/features/channels/components/channels-table.tsx` 中，当 `myChannelsOnly=true` 时，查询参数构造逻辑强制将 `scope` 参数设为 `undefined`，忽略了用户通过筛选器选择的 `scope` 值。

具体位置：
- 第 211-216 行：`queryKey` 中的 `scope` 参数在 `myChannelsOnly=true` 时被强制设为 `undefined`
- 第 241-246 行：`queryFn` 中的 `commonParams.scope` 同样被强制设为 `undefined`

但 UI 中的筛选器（第 429-437 行）仍然包含 `scope` 筛选器，且选项为 `[All, Public, Private]`，造成用户可以点击但没有效果的 bug。

**修复方案：**
移除 `myChannelsOnly` 对 `scope` 参数的屏蔽，使「我的渠道」页面也能正常使用 Public/Private 筛选。

**修改的文件：**
- `web/default/src/features/channels/components/channels-table.tsx` — 移除两处 `myChannelsOnly ? undefined :` 三元判断，使 `scope` 参数正常传递
