## 修复：排行榜排序与排名标准不一致

**问题：** 排行榜中评分高的排在评分低的下面。例如：排名 8（score 16.1）排在排名 9（score 26.4）上面。

**根因：** 后端 `GetModelPerformanceList` 使用 `ORDER BY tps DESC, ttft ASC` 排序，但前端排名基于综合评分（score = TPS×60% + TTFT×40%）。排序标准和排名标准不一致。

**修复：** `model/model_performance.go` 中 `GetModelPerformanceList` 改为：
1. 查询所有符合条件的记录（不再用数据库分页）
2. 在内存中计算每条记录的 score
3. 按 score 降序排序
4. 手动分页并赋予正确排名

**潜在影响：** 数据量较大时会有内存开销，但测试渠道性能数据通常数量有限，影响可控。

## 修复：排行榜采样次数始终显示0

**问题：** 模型响应速度排行榜中每条数据都显示"采样 0 次"。

**根因：** `ModelPerformanceItem` 结构体（返回给前端的 DTO）缺少 `sample_size` 字段。数据库查询时已通过 `model_performances.*` 取出 `sample_size`，但组装返回数据时未将其传入 `ModelPerformanceItem`，导致前端收到 `undefined`，`undefined || 0` 显示为 0。

**修复文件：** `model/model_performance.go`
1. 给 `ModelPerformanceItem` 添加 `SampleSize int \`json:"sample_size"\`` 字段
2. 在 `GetModelPerformanceList` 组装条目时传入 `r.SampleSize`

## 测试渠道与测试模型的概念澄清

用户提问：一个渠道的测试模型如何设置多个？

**现状：**
- `test_model`（默认测试模型）：仅用于管理员手动点击"测试"按钮时的默认模型，位于基础配置区
- `is_test_channel`（设为测试渠道）：位于高级设置 → 模型性能采样设置，启用后该渠道所有模型都会被定时采样

**关键代码：**
- `controller/channel-test.go:82-92`：`test_model` 只影响手动测试，没填就取模型列表第一个
- `model/sampling_task.go:42-46`：采样任务已遍历 `channel.GetModels()` 全部模型

**结论：** `test_model` 和 `is_test_channel` 是两个独立功能，前者服务手动测试，后者服务自动采样。测试渠道的自动采样已经覆盖该渠道所有模型，无需额外设置"多个测试模型"。
