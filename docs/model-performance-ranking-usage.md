# 模型性能排行榜使用文档

## 一、功能概述

模型性能排行榜用于对系统接入的所有 AI 模型进行自动化的性能采样与排名，帮助管理员和玩家了解各模型的实际响应速度表现。

排行榜基于两个核心指标计算综合评分：

- **TPS（Tokens Per Second）**：模型每秒生成的 Token 数，越高越好
- **TTFT（Time To First Token）**：首 Token 响应延迟，越低越好

系统会定期（或手动）对「测试渠道」下的所有模型发送统一 Prompt 进行采样，根据响应结果计算排名。

---

## 二、核心概念

### 2.1 测试渠道

测试渠道是专门用于性能采样的渠道，与普通渠道完全隔离：

| 维度 | 测试渠道 | 普通渠道 |
|------|----------|----------|
| 用途 | 模型性能自动采样 | 玩家正常调用 |
| 可见性 | 仅管理员可见 | 所有用户可见 |
| 玩家调用 | 不会路由到测试渠道 | 正常路由 |
| 模型列表 | 参与排行榜排名 | 不参与排行榜 |

**关键规则**：只有被标记为「测试渠道」的渠道，其下的模型才会被采样并进入排行榜。

### 2.2 综合评分

排行榜的最终排名依据是**综合评分**，计算公式为：

```
score = TPS得分 × 60% + TTFT得分 × 40%
```

- TPS 和 TTFT 各自以管理员配置的「基准值」为满分标准进行归一化
- 基准值越高，获得高分的难度越大
- 修改基准值会立即影响所有历史数据的排名显示

## 三、使用流程

### 3.1 配置测试渠道

**路径**：渠道管理 → 编辑渠道 → 高级设置

1. 找到需要参与性能测试的渠道
2. 进入渠道编辑页面，切换到「高级设置」标签
3. 勾选「设为测试渠道」
4. 保存后，该渠道下的所有模型将自动纳入采样范围

**注意事项**：
- 一个渠道被设为测试渠道后，普通玩家在模型选择列表中**看不到**该渠道及其模型
- 玩家请求也**不会**被路由到测试渠道
- 只有采样任务和排行榜可以访问测试渠道

### 3.2 配置采样参数

**路径**：系统设置 → 模型相关设置 → 模型性能采样（页面顶部卡片）

采样配置包含三个 Section：

#### 采样基准设置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| TPS 基准 | TPS 评分达到满分的标准值（tokens/s） | 100 |
| TTFT 基准 | TTFT 评分达到满分的标准值（ms） | 1000 |

**建议**：根据你接入的模型档次调整基准。如果主要接入的是高端模型，可适当提高基准值使排名更有区分度。

#### 采样配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 采样 Prompt | 发送给模型进行性能测试的 Prompt 内容 | 空 |
| Max Tokens | 采样请求的最大输出 Token 数 | 2048 |

**建议**：
- Prompt 建议设置为一个能稳定触发模型输出的内容，长度适中
- Max Tokens 不宜过小，否则无法充分测试模型的 TPS 表现

#### 定时采样

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 采样时间段 | 每天允许执行自动采样的时间范围 | 00:00 - 23:59 |
| 采样间隔 | 每隔多少分钟执行一次采样（分钟） | 30 |

**设置示例**：

```
每天 06:00 到 22:00，每隔 30 分钟执行一次
```

**特殊规则**：
- 间隔设为 **0** 表示关闭定时采样
- 支持跨天时间段，如 `22:00` 到 `06:00` 表示夜间采样
- 不在采样时间段内时，即使到了间隔时间点也会跳过

#### 立即执行采样

点击「立即执行采样」按钮可手动触发一次采样任务，无需等待定时器。适合在修改配置后立即验证效果。

采样执行过程中会显示实时进度卡片，包含：
- 已完成 / 总任务数
- 成功 / 失败数
- 当前正在采样的渠道和模型
- 进度条

### 3.3 查看排行榜

**入口**：
- 顶部导航栏「模型排行」
- 侧边栏控制台「模型排行」

**页面说明**：

排行榜列表每行展示：

| 字段 | 说明 |
|------|------|
| 排名徽章 | 第1名金色、第2名银色、第3名铜色、其余普通灰色 |
| 模型名 | 模型标识名称，可点击跳转到定价页性能详情 |
| 供应商 | 所属供应商名称 |
| Avg TPS | 每秒 Token 数，颜色标识档次，可点击排序 |
| Avg TTFT | 首 Token 延迟（ms），颜色标识档次，可点击排序 |
| 成功率 | 请求成功率百分比，可点击查看详情 |
| 评分 | 综合评分（0-100+），颜色标识档次，可点击排序 |

**排序功能**：

- 点击 **Avg TPS**、**Avg TTFT**、**评分** 列头可切换排序
- 默认按综合评分降序（`sort_by=score&sort_order=desc`）
- 点击同一列头切换升序↔降序，点击不同列头默认降序
- 当前排序列显示箭头指示方向（↓ 降序 / ↑ 升序）
- 排序状态保存在 URL 参数中，可分享链接

**颜色标识规则**：

| 指标 | 优秀（绿色） | 良好（蓝色） | 一般/较差（橙色/红色） |
|------|-------------|-------------|----------------------|
| 综合评分 | ≥ 80 | ≥ 60 | < 60 |
| TPS | ≥ 基准 × 80% | ≥ 基准 × 40% | < 基准 × 40% |
| TTFT | ≤ 基准 × 30% | ≤ 基准 × 80% | > 基准 × 80% |

**搜索**：支持按模型名称关键词过滤。

## 四、管理员配置

### 4.1 控制排行榜入口可见性

**路径**：系统设置 → 运营设置 → 顶部导航模块

管理员可勾选/取消勾选「模型排行」，控制顶部导航和侧边栏是否显示该入口。

**权限规则**：
- 管理员（root/admin）始终可以访问排行榜页面
- 普通用户只有在入口开启时才能看到和访问

### 4.2 渠道管理中的测试渠道筛选

**路径**：渠道管理

渠道列表中新增了「测试渠道」列（仅管理员可见），显示该渠道是否为测试渠道。

筛选器中也新增了「渠道类型」选项：
- 全部渠道
- 普通渠道
- 测试渠道

## 五、常见问题

### Q1：为什么排行榜上有些模型显示「采样 0 次」？

A：该模型所在渠道尚未被设为测试渠道，或采样任务尚未执行过。请将对应渠道设为测试渠道，并触发一次采样。

### Q2：测试渠道会影响正常玩家使用吗？

A：不会。测试渠道对普通用户完全不可见，也不会接收任何玩家请求，仅用于后台采样。

### Q3：修改 TPS/TTFT 基准值会影响历史排名吗？

A：会。基准值修改后立即生效，所有历史数据的得分会按新基准重新计算并重新排名。

### Q4：可以只对部分模型采样吗？

A：目前采样粒度是渠道级别的。将渠道设为测试渠道后，该渠道下的**所有模型**都会被采样。如需排除特定模型，请将其单独放到非测试渠道中。

### Q5：定时采样时间段支持跨天吗？

A：支持。例如设置 `22:00` 到 `06:00`，系统会在每天 22:00 到次日 06:00 之间按间隔执行采样。

### Q6：为什么渠道编辑页里有「测试模型」和「设为测试渠道」两个设置？

A：
- **测试模型**（基础配置区）：仅用于管理员手动点击「测试」按钮时的默认模型，和自动采样无关
- **设为测试渠道**（高级设置）：启用后该渠道所有模型都会被定时自动采样，进入排行榜

两者功能独立，互不干扰。

## 六、技术备注

- 采样任务使用系统后台 goroutine 定期执行，服务重启后会自动恢复定时器
- 同一时刻只会执行一个采样任务，避免重复采样
- 采样失败（如渠道超时、模型报错）不会影响其他模型的采样，失败记录会计入失败次数
- 排行榜数据存储在 `model_performances` 表中，按模型+渠道维度聚合
